# Cloak v0.4.0 Roadmap Design Record

This document records the roadmap that shipped in `v0.4.0` and the implementation decisions that survived the release.

## Context

`v0.3.0` shipped the core steganography toolkit, but it left six follow-up improvements for the next cycle. `v0.4.0` closes that list across `cloak-core`, `cloak-cli`, and `fuzz/` while keeping the encrypted wire format on version `1`.

## Shipped Roadmap Items

### 1. Versioned Wire Format

- Shipped: `WireVersion`, `detect_version()`, `UnsupportedVersion`, and version-dispatched decryption.
- Design choice kept: `encrypt()` still writes `v1` only. The release adds routing and explicit rejection for unknown versions without changing the current ciphertext layout.

### 2. Parallel Embedding

- Shipped: the optional `parallel` feature in `cloak-core`, `EmbedOptions.parallel`, CLI `--parallel`, and `embed_lsb_parallel()`.
- Design choice kept: parallelism is transparent. The output image and embedded wire format remain compatible with sequential mode, and small images fall back to the sequential path.

### 3. Enhanced Capacity Reporting

- Shipped: `capacity_report()` returning `CapacityReport` with nested `CapacityBreakdown`, plus detailed CLI capacity output.
- Design choice kept: block-alignment and crypto overhead stay visible in the report so the published usable-byte count matches real embed limits.

### 4. GIF-Specific Steganalysis

- Shipped: palette anomaly detection, EzStego detection, gifshuffle detection, and palette chi-square heuristics through `analysis::analyze_gif()`.
- Design choice kept: analyze the first frame and the available palette tables without changing the generic image-analysis API surface.

### 5. Property-Based Testing

- Shipped: five proptest suites covering roundtrip behavior, analysis invariants, capacity math, crypto behavior, and format detection.
- Design choice kept: generated images stay bounded for CI runtime while still exercising odd and prime dimensions that stress pixel math.

### 6. Fuzz Targets

- Shipped: six cargo-fuzz targets for extract, embed, analyze, decrypt, format detection, and wire-format parsing.
- Design choice kept: fuzzing remains nightly-only and outside the default CI gate.

## Verification

`make check` is the required merge gate for this release:

```bash
cargo fmt --all --check
cargo clippy --workspace -- -D warnings
cargo test --workspace
```

Additional hardening remains available when needed:

- `cargo bench --package cloak-core` for embedding-path performance work
- `cargo +nightly fuzz run <target>` for fuzz smoke tests

## Release State

- Workspace crate versions are already set to `0.4.0`.
- `CHANGELOG.md`, `README.md`, `SECURITY.md`, and `HANDOFF.md` are aligned on the shipped `0.4.x` state.
- `docs/` is intentionally included in this branch so this design record stays with the release history.
- Public publish, tagging, and GitHub release creation are separate release-operations steps after merge.
